# 博客文档一体化维护 Skill

## 适用范围与联动

**目标文档**：`src/` 下递归所有层级全部 `.md`（含 read/concept/work/practice/about/vitepress 等所有子目录）。

**枚举方式**：必须递归（含任意层级子目录），用编辑器文件树或 glob `src/**/*.md`；不得以单层目录结果判定"无文档"。

**联动文件**（改文档必须同步维护）：

- `src/术语词汇表.json`
- `src/文档元数据.json`
- `config/themeConfig/sidebar/` 下各 ts
- `config/vite/rewrites.ts`、`config/themeConfig.ts` / `nav.ts`
- 全仓 md 内链

**进度文件**（按阶段分）：

- `skills/blog/content-fix/PROGRESS.md` 与 `PROGRESS_SRC.md`
- `skills/blog/file-rename/PROGRESS_FILE_RENAME.md`
- `skills/blog/file-rename/RENAME_SUGGESTIONS.json`（fallback 映射）
- `skills/blog/tech-review/PROGRESS_TECH_REVIEW.md`
- `skills/blog/json-guard/PROGRESS_JSON_GUARD.md`

---

## 执行流水线（总控）

四阶段按序执行，每阶段独立回写 PROGRESS，可单独触发也可串联。

| 阶段          | 目标       | 核心动作                                                                                       |
| ------------- | ---------- | ---------------------------------------------------------------------------------------------- |
| ① content-fix | 内容优化   | frontmatter 迁移删除、标题优化、元数据一致性校验、去AI化改写、术语打标签、结构补充、文件名优化 |
| ② file-rename | 文件名兜底 | 补充检查文件名与主题契合度，不契合的改名或落 fallback                                          |
| ③ tech-review | 技术审查   | 事实正确性、代码示例、一致性、链接引用；只查对错不润色                                         |
| ④ json-guard  | 数据兜底   | JSON 语法修复、重复键合并、元数据全量覆盖、路径-内容一致性校验、词汇表规范化                   |

**接管检查**（每次会话开始必做）：

1. 读全部 PROGRESS 文件
2. 查看编辑器「源码管理」面板变更列表（不得跑 git 命令）
3. 汇报断点：未处理文档、半成品 JSON、未同步改名、残留 frontmatter
4. 文件不存在则盘点后创建

---

## 阶段一：content-fix（内容优化）

### 执行流程（逐篇按序）

1. 递归枚举 `src/**/*.md` 确认处理范围
2. 读取联动 JSON/配置，以现有字段结构为准，不得自创新字段
3. **文件名优化**：不符合规范者按「文件名优化规范」改名并完成四项同步
4. **迁移 frontmatter**（强制逐篇检查）：
   - 文档头部若存在 `--- ... ---` 块，将字段写入 `文档元数据.json`（以路径为键，已存在则合并更新）
   - 随后删除该块，回读前 3 行确认无 `---` 残留
   - 无则跳过
5. **标题优化**：按「标题优化规范」处理所有层级标题文字
6. **元数据-内容一致性校验**：按「元数据校验规范」核对 `文档元数据.json` 中该文档条目
7. **改写正文**：遵守「去AI化与表达规范」
8. **术语打标签**：遵守「术语标注规范」，同步写入词汇表
9. **补充结构**：遵守「结构补充规范」
10. 对照「禁止事项」「自检清单」逐项检查
11. 每批结束回写 PROGRESS，给出建议 commit 命令文本

### 标题优化规范

标题（`#` ~ `######`）文字纳入优化范围：

- 术语规范化：执行首字母大写与全称规则（与正文一致）
- 去冗余：删除"关于…的介绍""浅谈""学习笔记"等修饰
- 去AI味：删除"让我们了解""一文搞懂"等套话
- 一级标题优化后若文件名不一致，须同步改名
- **标题中不打 `<word>` 标签**
- 标题层级结构不变，只改文字表达

### 元数据校验规范

逐篇核对 `文档元数据.json` 中该文档条目：

- **path**：必须与实际相对路径完全一致（含已改名文档），不符即修元数据
- **title**：必须与文档当前一级标题完全一致，不一致→以文档实际一级标题为准更新
- **tags**：与文档主题明显不符时修正；无 tags 字段则按现有结构给空值
- **缺失条目**：文档无条目→立即补齐（title 取一级标题，path 取相对路径，其余按现有结构给空值）
- 不得自创字段、不得删除既有条目

### 文件名优化规范

命名约定：简洁语义化中文，原则上与一级标题一致（去标点）；术语写法与词汇表一致；禁止空格/标点/特殊字符/无意义编号。已契合的不改。

改名方式：编辑器重命名功能或文件工具，禁止终端命令。

**改名后强制四项同步**（缺一即视为未完成）：

1. `src/文档元数据.json` 的 path/文件名字段
2. `config/themeConfig/sidebar/` 对应文件该条目 link
3. `config/vite/rewrites.ts`、nav 等涉及旧名的映射
4. 全仓其他 md 指向旧名的引用链接

完成后全仓搜旧名（带 `.md` 与不带两种形式）确认零残留。

### 术语标注规范

**不可变区域**（一个字符都不得修改）：

- 围栏代码块（` ``` ` 起止之间的全部内容）
- 行内代码（` ` ` 反引号包裹的文本）
- 链接文本与链接地址

标题已移出不可变区域（按标题规范处理，但不打标签）。

**打标签为强制动作**：目标范围内所有文档均须打标签并入表；不得以目录/风格为由跳过。

**禁止全局批量替换**：每一处按上下文判断，仅自然语言正文才打标签。

**术语范围**：产品、框架、协议、算法、文件格式、行业专有名词。

**全称规则**：TS→TypeScript、JS→JavaScript；行业固有缩写（SVG、CSS、API、JSON、URL、PNG、WebP、GIF）保留。

**排除清单**（不打标签不入表）：v-\* 指令、ref/reactive/computed 等 API 标识符、requestAnimationFrame 等函数名、通用编程词汇。

**首字母大写**：lottie→Lottie、canvas→Canvas、base64→Base64；官方固定写法保持。

**标签语法**：先搜仓库 `<word` 既有用法借用其风格；无则用 <word text="术语" />。

同一段落同一术语只打一次；已打过标签的保持原样，写法不合规则修正并同步词汇表。

### 去AI化与表达规范

- 删除套话：「让我们」「你可以」「众所周知」「总之」「值得一提的是」、emoji、感叹号堆叠
- 结论先行：段首一句结论再给理由；多用陈述句祈使句，句子缩短
- 同一概念全文只用词汇表唯一术语（全称），禁止同义替换与缩写混用
- 只改表达不改事实：代码、命令、链接、数值保持原样

### 结构补充规范

- 代码：统一带语言标签围栏代码块；补语言标签只改围栏起始行，不改内部
- 表格：三项以上对比必须用表格
- 流程图：Mermaid（flowchart / sequenceDiagram）；未集成则编号步骤
- 标题层级最深 `###`，不跳级

## 阶段二：file-rename（文件名兜底）

### 判断标准

- 读文档一级标题 + 首段 + 各小节标题，归纳主题
- 文件名与主题不契合（文不对题、过于宽泛、无意义编号、英中混拼等）→ 进入改名流程
- 命名约定同 content-fix
- 已契合的不改

### 执行流程

1. 用编辑器重命名/文件工具改名（禁止终端命令）
2. 四项同步（同 content-fix 文件名优化规范）
3. 全仓搜旧名确认零残留
4. 无法改名（引用依赖过复杂、存在冲突、无把握）→ 不得硬改，写入 `RENAME_SUGGESTIONS.json`：`{ "src/xxx/旧名.md": "新名.md", ... }`，并在 PROGRESS 注明原因

**本阶段只改名与同步，不改文档内容。**

## 阶段三：tech-review（技术审查）

### 审查维度（逐篇逐项）

- **事实正确性**：API 描述是否符合官方行为；原理性叙述有无概念错误或过度概括；版本敏感项以当前稳定版为基准
- **代码正确性**：示例有无语法错误、逻辑 bug、变量名不一致、缺依赖；输出注释是否与实际运行结果一致
- **一致性**：上下文是否自相矛盾；术语写法是否与词汇表一致（仅改写法不改含义）
- **链接与引用**：链接目标、引用图表是否存在

### 处理分级

- **直接修**：有完全把握的明确错误 → 直接修正，保持原文表达风格
- **修并记录**：把握高但涉及表述重组 → 修正并在 PROGRESS 记录改动点
- **只报告不改**：不确定/版本差异/有争议 → 写入 PROGRESS「待人工确认」清单，不得改动原文

### 代码块规则（与 content-fix 的差异）

本阶段允许修改代码块，但仅限修正明确错误；不重写代码风格、不增删注释、不改标识符命名（标识符本身是错的除外）。

### 进度与批次

每批 5 篇；批末回写 PROGRESS：每篇结论（通过 / 修正 N 处 / 待确认 N 条）；给出建议 commit 命令文本。

## 阶段四：json-guard（数据完整性兜底）

### 核心职责

**语法修复**：字符串内未转义双引号一律改为「」；补缺失逗号、去尾逗号、补闭合；修完以编辑器 JSON 语言模式确认零报错零警告。

**重复键合并**：同层重复对象键，保留字段更全、内容正确的一条，合并另一条独有内容后删除重复；合并不得丢数据。

**元数据全量覆盖**：递归枚举 `src/` 下所有层级全部 `.md`（用户指定排除的除外），无论有无 frontmatter，凡 `文档元数据.json` 无条目者一律补齐：title 取一级标题（无则取文件名）、path 为相对路径、tags/authors 等按现有结构给空值，不得自创字段。

**元数据-内容一致性校验**：

- **path 存在性**：path 指向的文件必须实际存在；文件不存在→标记异常，不删除条目，写入 PROGRESS 待人工确认
- **title 一致性**：元数据 title 必须与文档当前一级标题完全一致；不一致→以文档实际一级标题为准更新
- **tags 合理性**：tags 与文档内容主题明显不符时修正
- **反向校验**：实际存在但元数据无条目的文档→立即补齐

**词汇表规范化**：去重（大小写不敏感，保留官方写法）；全称/大写规则（TS→TypeScript 等）；清理排除清单条目（v-\*、ref、computed、requestAnimationFrame 等）。

**路径一致性**：元数据条目 path 与实际文件路径逐一核对（含已改名文档），不符即修。

### 写入防错约定（预防复发）

- 写任何条目前先搜索键是否存在：存在=更新，不存在=追加
- descript 等字符串内禁止裸双引号，引用一律用「」
- 每批写入后回读文件，确认 JSON 可解析、无重复键
- 不删既有条目、不臆造字段

## 公共规则

### 终端零命令约束

禁止执行任何终端命令（PowerShell/cmd/bash/git/npm 等）：

- 改名：编辑器重命名
- 搜索：编辑器全仓搜索
- 读写：文件编辑工具
- 提交：只给建议命令文本
- 确需命令的操作停下请示用户

### 进度落盘与中断恢复

每批结束更新对应 PROGRESS，模板：

```
# <阶段名> 进度

## 最后更新

<时间>（第 N 批完成）

## 已处理
src/xxx.md（含改动说明）

## 未处理

src/yyy.md

## 待办事项

<未完成项>

## 统计

词汇表共 N 条（本批新增 M）；元数据共 N 条（本批新增 M）
```

新会话先执行接管检查，不重复已处理、不遗漏未处理。
每批给出建议 commit 命令文本由用户手动执行。

### 禁止事项（全局）

- 不得执行任何终端命令
- 不得保留 `---` frontmatter 块
- 不得将缩写（TS/JS）登记入词汇表（固有缩写除外）
- 不得修改代码块/行内代码内任何字符（tech-review 修正明确错误除外）
- 不得用全局查找替换批量打标签或改大小写
- 不得移动文档目录（须用户确认）
- 不得跳过任何目录的术语打标签
- 不得用非递归枚举断定无 md
- 不臆造 JSON 字段、不删除既有条目
- 不得将排除清单标识符写入词汇表
- 不得在标题中插入 `<word` 标签
- 不确定的技术事实保留原文，不得编造
- 正常结束前不得跳过 PROGRESS 回写

### 自检清单（全局）

- [ ] 会话开始已执行接管检查
- [ ] 未执行任何终端命令
- [ ] src/ 递归枚举无遗漏
- [ ] 已处理文档无 frontmatter 残留
- [ ] 词汇表无缩写条目（固有缩写除外）
- [ ] 正文术语均已打标签（标题/代码块/行内代码/链接除外）
- [ ] 标题已按规范优化，未插入标签
- [ ] 代码块/行内代码内无任何改动（tech-review 修正除外）
- [ ] 打标签逐处判断，未用全局替换
- [ ] 文件名与一级标题一致；改名四处同步且零残留
- [ ] 元数据条目 path/title 与实际文档一致
- [ ] 词汇表无排除清单标识符
- [ ] 无去AI化黑名单词残留
- [ ] 代码块语言标签齐全
- [ ] 两个 JSON 编辑器语言模式零报错零警告
