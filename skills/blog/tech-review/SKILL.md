# 博客文档技术审查 Skill

## 适用范围

- 递归枚举 `src/read/`、`src/concept/`、`src/work/`、`src/practice/` 下全部 `.md`。
- 与 content-fix 分工：本技能只管"对不对"，不管"好不好读"；
  表达/术语/格式问题移交 content-fix，不在本技能处理。
- 进度文件：`skills/blog/tech-review/PROGRESS_TECH_REVIEW.md`。

## 审查维度（逐篇逐项）

1. 事实正确性：API 描述是否符合官方行为；原理性叙述（事件循环、渲染、编译、响应式等）
   有无概念错误或过度概括；版本敏感项以当前稳定版为基准。
2. 代码正确性：示例有无语法错误、逻辑 bug、变量名不一致、缺依赖；
   输出注释（如 //35）是否与实际运行结果一致。
3. 一致性：上下文是否自相矛盾；术语写法是否与词汇表一致（仅改写法不改含义）。
4. 链接与引用：链接目标、引用图表是否存在。

## 处理分级

- **直接修**：有完全把握的明确错误（语法错、变量名不一致、输出不符、明显事实错误）→
  直接修正，保持原文表达风格；
- **修并记录**：把握高但涉及表述重组 → 修正并在 PROGRESS 记录改动点；
- **只报告不改**：不确定/版本差异/有争议 → 写入 PROGRESS「待人工确认」清单
  （文档路径 + 原文 + 疑问点），不得改动原文。

## 代码块规则（与 content-fix 的差异）

- 本技能**允许修改代码块**，但仅限修正明确错误；
- 不重写代码风格、不增删注释、不改标识符命名（标识符本身是错的除外）。

## 禁止事项

- 不得编造事实"圆"原文；不确定一律只报告；
- 不得做去AI化、术语打标等表达层改写；
- 不得改名/移动文档；不得执行任何终端命令。

## 进度与批次

- 每批 5 篇；批末回写 PROGRESS：每篇结论（通过 / 修正 N 处 / 待确认 N 条）；
- 给出建议 commit 命令文本，由用户手动执行。

## 自检清单

- [ ] 每篇审查文档均有结论记录
- [ ] 修正项均含文档路径 + 改动摘要
- [ ] 不确定项零改动，全部入待人工确认清单
- [ ] 本会话未执行终端命令，PROGRESS 已回写
