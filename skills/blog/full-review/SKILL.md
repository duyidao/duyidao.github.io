# 博客文档全量重审 Skill

## 适用范围

- 递归枚举 `src/` 下全部 `.md`（任意层级深度：子级、孙级、曾孙级目录一律不遗漏）；用 glob `src/**/*.md` 或编辑器文件树枚举，不得以单层目录结果判定"无文档"。
- 包含 `read/`、`concept/`、`work/`、`practice/`、`about/` 等一切子目录。
- 本次为**重审**：`tech-review` 已有结论的文档也须逐篇复查（重点查漏项、`<word>` 空格、标题、格式基线），不得以"已审过"为由跳过。
- 与 `content-fix` 分工：本技能只管"对不对"、"`<word>` 空格合规"、"标题是否合理"、"格式基线达标"，不管"好不好读"；表达/术语/去AI化问题移交 `content-fix`。
- 进度文件：`skills/blog/full-review/PROGRESS_FULL_REVIEW.md`（不存在则创建；接管时先读既有内容）。

## 审查维度（逐篇逐项）

### 事实正确性

API 描述是否符合官方行为；原理性叙述（事件循环、渲染、编译、响应式等）有无概念错误或过度概括；版本敏感项以当前稳定版为基准。

### 代码正确性

示例有无语法错误、逻辑 bug、变量名不一致、缺依赖；输出注释（如 `//35`）是否与实际运行结果一致。

### 一致性

上下文是否自相矛盾；术语写法是否与词汇表一致（仅改写法不改含义）。

### 链接与引用

链接目标、引用图表是否存在。

### `<word>` 空格专项

- 正确例子：`啊 <word text="术语" /> 啊` —— 标签前后各一个半角空格；
- 错误例子：`啊<word text="术语" />啊` —— 标签前或后缺空格。

修正规则：

1. 标签前字符为非空白（汉字/字母/数字/标点）→ 补一个半角空格；
2. 标签后字符为汉字/字母/数字 → 补一个半角空格；
3. 标签后紧跟 `，。！？、；：）」】` 等标点 → 其后不补空格（排版惯例）；
4. 标签处于行首/行尾时该侧不补；已有空格不重复添加；
5. 只允许增删空格，不得改标签名、属性、闭合方式及周围文字；
6. 不得新增 `<word>` 标签（打标签归 `content-fix`），本技能只纠正既有标签的空格。

### 标题优化专项（知识文档化；无需人工确认，一律直接修改）

1. **H1 契合主题**：每篇仅一个 H1，内容与文档主题契合（原则上与文件名一致）；宽泛 H1（如 `# Vue`、`# CSS`）→ 展开为具体主题。
2. **语义自明**：标题须脱离上下文可读；裸泛标题（`含义`、`语法`、`例子`、`用法`、`总结`、`注意`）一律补主题前缀。
3. **消重（MD024）**：同文档内标题文字不得重复；重复者用父级主题前缀区分。
4. **层级**：不跳级（`##` 不得直跳 `####`）；深度原则上最深到 `###`：既有 `####` 内容独立者降为 `###` 并语义自明命名，内容仅数行者改为加粗引导段 `**...**`。
5. **标题内 `<word>` 清理**：标题中含 `<word ... />` 标签 → 删除整个标签、保留标题纯文本；删后标题为空 → 按文件名/主题语义命名；删除视同标题改动，执行锚点同步。
6. **加粗当标题（MD036）**：独立成行、实际充当小节标题的 `**加粗**`（其后跟随表格/列表/段落）→ 改为相应层级标题（按上下文层级补齐，原则上不超过 `###`）并语义自明命名；若加粗仅为段内强调（不充当标题）→ 不改。
7. **锚点同步（自主完成，不请示）**：改标题后必须全仓搜索 `#旧标题` 与 `文件名.md#旧标题` 两种引用；有引用直接同步，零残留；无引用记录"无锚点引用，无需同步"后继续。
8. 不得向标题**新增** `<word>` 标签；不得借改标题做术语打标/大小写修正。
9. 所有标题改动按目录分组回写 PROGRESS（格式见「标题优化记录规范」）。

示例：

| 修正前                               | 修正后                    | 说明                     |
| ------------------------------------ | ------------------------- | ------------------------ |
| `# Vue`                              | `# Vue 动态组件`          | H1 契合文件名/主题       |
| `### 含义`                           | `### 插槽的含义`          | 裸泛标题补主题前缀       |
| `#### 语法`                          | `### 插槽的语法`          | 降一级 + 消重            |
| `#### 例子`                          | `### 插槽示例`            | 降一级 + 语义自明        |
| `**ColorThief 主要方法**`            | `### ColorThief 主要方法` | MD036 加粗当标题改真标题 |
| `## 页面截图 <word text="Canvas" />` | `## 页面截图`             | 标题内 `<word>` 标签清理 |

### 格式基线专项（markdownlint；无需人工确认，直接修）

直接修白名单（纯空白/空行/换行类，不涉内容语义）：

1. **MD047 single-trailing-newline**：文件必须以**单个换行符**结尾；缺末尾换行、或末尾多个空行 → 直接修；
2. **MD009 no-trailing-spaces**：行尾空格一律删除；
3. **MD012 no-multiple-blanks**：连续多个空行压缩为一个空行；
4. **MD022 blanks-around-headings**：标题上下各保留一个空行；
5. 标题类警告（MD024/MD025/MD036）→ 归「标题优化专项」处理，不在本专项跳过。

MD047 修正手法（仅编辑器工具，禁终端）：

1. 优先 Edit 工具：old_string 取「文件最后一行的实际内容」（非空、非整文件），new_string = 该行内容 + 一个 `\n`；
2. Edit 报"新旧相同/匹配失败"时 → 改用 Write 工具整文件回写，结尾统一整理为单个 `\n`（顺带压缩末尾多空行）；
3. 两者皆失败 → 停下汇报，不得自行改用 `Add-Content` / `cmd` / `echo` 等终端变通。

边界规则：

- 以上修正**只作用于不可变区域之外**；代码块/行内代码内被 lint 报同类问题 → 跳过，只报告不改；
- 涉及内容语义的警告（行宽、列表样式、内联 HTML 等）→ 只报告不改，记入 PROGRESS；
- 格式修正逐文件记录：`格式修正 N 处（MD047×1、MD012×2…）`。

## 标题优化记录规范（按目录归档）

PROGRESS 中设独立章节「标题优化记录」，按文件所属目录分组，逐文件列出新旧标题对照：

```
## 标题优化记录

### src/concept/vue/vue2/
- 动态组件.md
  - `# Vue` → `# Vue 动态组件`
  - `### 含义` → `### 插槽的含义`
  - `#### 语法` → `### 插槽的语法`
  - `#### 例子` → `### 插槽示例`

### src/concept/chart/canvas/
- 色彩提取.md
  - `**ColorThief 主要方法**` → `### ColorThief 主要方法`（MD036）
- 页面截图.md
  - `## 页面截图 <word text="Canvas" />` → `## 页面截图`（标题内标签清理）

### src/work/a/
- xxx.md
  - `## 概述` → `## xxx 概述`
```

要求：

- 目录粒度与实际路径一致（如 `src/work/a/`、`src/work/b/`）；
- 同目录多篇可并列（用 `、` 分隔文件名），但每篇的改动对照不得省略；
- 只列被改标题的文件；未改动的文件不出现；
- 每条对照须含完整旧标题与新标题（带 `#` 层级符号；MD036 转换与 `<word>` 清理须注明类型）；
- 每篇的锚点同步结果（已同步 N 处 / 无锚点引用无需同步）随该篇对照附记。

## 不可变区域（一个字符都不得修改）

- 围栏代码块（` ``` ` 起止之间的全部内容，含代码、注释、输出示例）；
- 行内代码（反引号包裹的文本）；
- 链接文本与链接地址。

> 标题**不属于**不可变区域：标题优化（含 MD036 转换、标题内 `<word>` 清理）无需人工确认，直接修改并完成锚点同步。
> 格式基线修正不得进入不可变区域；区域内 lint 警告只报告。
> 不可变区域内若出现 `<word` 标签 → 不得改动，写入「待人工确认」清单。

## 处理分级

| 级别           | 触发条件                                                                                                                                                                     | 动作                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **直接修**     | 明确错误（语法错、变量名不一致、输出不符、明显事实错误、`<word>` 空格缺失）；标题优化与锚点同步（含 MD036、标题内 `<word>` 清理）；格式基线白名单（MD047/MD009/MD012/MD022） | 修正，不请示                                                                          |
| **修并记录**   | 把握高但涉及表述重组                                                                                                                                                         | 修正并在 PROGRESS 记录改动点                                                          |
| **只报告不改** | 事实类不确定/版本差异/有争议；代码块内 lint 警告；涉及内容语义的 lint 警告                                                                                                   | 写入 PROGRESS「待人工确认」或「只报告」清单（文档路径 + 原文 + 疑问点），不得改动原文 |

## 禁止事项

- 不得编造事实"圆"原文；事实类不确定一律只报告；
- 不得做去AI化、术语打标等表达层改写；
- 不得在标题中保留或新增 `<word>` 标签；
- 不得改名/移动文档；
- **绝对不得执行任何终端命令**：`powershell` / `cmd` / `bash` / `git` / `npm` / `Add-Content` / `Set-Content` / `echo` 及任何形式的嵌套调用（如 `powershell -Command`）；
  若 IDE 弹出「手动运行」终端审批，即说明已违规——立即放弃该方案，改用编辑器工具；
- 确需命令才能完成的操作：停下汇报并请示用户，不得自行变通；
- 不得就标题优化、格式基线向用户请示确认。

## 代码块规则

代码块属于「不可变区域」的组成部分，但本技能对其开一个例外：允许修正代码块内的**明确错误**（语法错、变量名不一致、输出与实际不符）。修正时遵循以下约束：

- 不重写代码风格、不增删注释、不改标识符命名（标识符本身是错的除外）；
- 代码块内空白/换行类 lint 警告一律跳过，只报告不改。

## 批次操作要求

每一处 `<word>`、每一个标题、每一处格式修正必须按上下文逐处判断，禁止全局查找替换批量操作；确需批量处理时，先将代码块替换为占位符（如 `<!--CODE_1-->`），操作完正文后再还原。

## 进度与批次

- 每批 5 篇；批末回写 PROGRESS：每篇结论（通过 / 修正 N 处 / 空格修正 N 处 / 标题修正 N 处 / 格式修正 N 处 / 待确认 N 条）；
- 「标题优化记录」章节按目录分组持续累积，批末不清零；
- 累计统计：累计修正（含空格、标题、格式）、累计通过、待人工确认、审查总篇数；
- 给出建议 commit 命令文本，由用户手动执行。
