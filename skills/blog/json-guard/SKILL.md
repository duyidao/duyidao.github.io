# 词汇表 / 元数据 JSON 完整性 Skill

## 目标文件

- `src/术语词汇表.json`
- `src/文档元数据.json`

## 核心职责

### 语法修复

字符串内未转义双引号一律改为「」；补缺失逗号、去尾逗号、补闭合；修完以编辑器 JSON 语言模式确认零报错零警告。

### 重复键合并

同层重复对象键，保留字段更全、内容正确的一条，合并另一条独有内容后删除重复；合并不得丢数据。

### 元数据全量覆盖

递归枚举 `src/` 下所有层级全部 `.md`（用户指定排除的除外），无论有无 frontmatter，凡 `文档元数据.json` 无条目者一律补齐：title 取一级标题（无则取文件名）、path 为相对路径、tags/authors 等按现有结构给空值，不得自创字段。

### 元数据-内容一致性校验

逐条核对元数据与实际文档：

- **path 存在性**：path 指向的文件必须实际存在；文件不存在→标记异常，不删除条目，写入 PROGRESS 待人工确认；
- **title 一致性**：元数据 title 必须与文档当前一级标题完全一致；不一致→以文档实际一级标题为准更新元数据；
- **tags 合理性**：tags 与文档内容主题明显不符时修正；
- **反向校验**：实际存在但元数据无条目的文档→立即补齐。

### 词汇表规范化

去重（大小写不敏感，保留官方写法）；全称/大写规则（TS→TypeScript 等）；清理排除清单条目（v-\*、ref、computed、requestAnimationFrame 等）。

### 路径一致性

元数据条目 path 与实际文件路径逐一核对（含已改名文档），不符即修。

## 写入防错约定（预防复发）

- 写任何条目前先搜索键是否存在：存在=更新，不存在=追加；
- descript 等字符串内禁止裸双引号，引用一律用「」；
- 每批写入后回读文件，确认 JSON 可解析、无重复键；
- 不删既有条目、不臆造字段。

## 终端零命令与进度

读写一律编辑器工具，禁止任何终端命令；
进度文件 `skills/blog/json-guard/PROGRESS_JSON_GUARD.md`：记录修复语法错误数、合并重复键清单、补录元数据清单、词汇表增删清单、路径-内容不一致修正清单；
批次结束给出建议 commit 命令文本由用户手动执行。
