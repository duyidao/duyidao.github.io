# 博客文档内容优化 Skill

## 适用范围

目标：`src/` 下递归所有层级全部 `.md` 文档（含 read/concept/work/practice/about/vitepress 等所有子目录）。
文档枚举必须递归（含任意层级子目录）：用编辑器文件树或 glob `src/**/*.md` 枚举；不得以单层目录结果判定"无文档"。
联动数据/配置文件（改文档必须同步维护）：

- 术语词汇表：`src/术语词汇表.json`
- 文档元数据：`src/文档元数据.json`
- 侧边栏路由配置：`config/themeConfig/sidebar/` 下各 ts
- VitePress 路由映射：`config/vite/rewrites.ts`、导航配置 `config/themeConfig.ts` / `nav.ts`
- 进度文件：`skills/blog/content-fix/` 下 `PROGRESS.md` 与 `PROGRESS_SRC.md`，接管时全部读取。

## 执行流程（逐篇按序，完成一篇再下一篇）

0. **接管检查**：会话开始时先读全部 PROGRESS 文件，并查看编辑器「源码管理」面板的变更列表（不得跑 git 命令），核对并汇报断点；文件不存在则盘点后创建。
1. **递归枚举** `src/**/*.md` 确认处理范围；读取各联动 JSON/配置，以 JSON 现有字段结构为准，不得自创新字段。
2. **文件名优化**：不符合规范者按「文件名优化规范」改名并完成四项同步。
3. **迁移 frontmatter**（强制逐篇检查）：文档头部若存在 `--- ... ---` 块，将字段写入 `文档元数据.json`（以文档路径为键，已存在则合并更新），随后删除该块，回读前 3 行确认无 `---` 残留；无则跳过。
4. **标题优化**：按「标题优化规范」处理所有层级标题文字。
5. **元数据-内容一致性校验**：按「元数据校验规范」核对该文档在 `文档元数据.json` 中的条目。
6. **改写正文**：遵守「去AI化与表达规范」（不可变区域一律不动）。
7. **术语打标签**：遵守「术语标注规范」——先识别不可变区域，再仅在自然语言正文中逐处打标签，并同步写入词汇表。
8. **补充结构**：遵守「结构补充规范」。
9. 对照「禁止事项」「自检清单」逐项检查。
10. 每批结束回写 PROGRESS，给出建议 commit 命令文本。
11. 全部完成后输出变更摘要，PROGRESS 标记完结。

## 标题优化规范

标题（`#` ~ `######`）文字纳入优化范围：

- 术语规范化：标题中的术语执行首字母大写与全称规则（与正文规则一致）；
- 去冗余：删除"关于…的介绍""浅谈""学习笔记"等冗余修饰，保留核心语义；
- 去AI味：删除"让我们了解""一文搞懂"等套话式标题；
- 一级标题优化后，若文件名与新一级标题不一致，须同步改名（走文件名优化流程）；
- **标题中不打 `<word>` 标签**；
- 标题层级结构不变（不增删标题、不调整层级），只改文字表达。

## 元数据校验规范

逐篇核对 `文档元数据.json` 中该文档条目与实际文档的一致性：

- **path**：元数据 path 必须与文档实际相对路径完全一致（含已改名文档）；不符即修元数据；
- **title**：元数据 title 必须与文档当前一级标题完全一致；不一致→以文档实际一级标题为准更新元数据（若一级标题刚被优化，用优化后的）；
- **tags**：元数据 tags 与文档内容主题明显不符时修正；无 tags 字段则按现有条目结构给空值；
- **缺失条目**：文档在元数据中无条目→立即补齐（title 取一级标题，path 取相对路径，其余按现有结构给空值）；
- 不得自创字段、不得删除既有条目。

## 文件名优化规范

命名约定：简洁语义化中文，原则上与文档一级标题一致（去标点）；术语写法与词汇表一致；禁止空格/标点/特殊字符/无意义编号。已契合的不改。
改名方式：编辑器重命名功能或文件工具，禁止终端命令。
改名后强制四项同步（缺一即视为未完成）：

1. `src/文档元数据.json` 的 path/文件名字段；
2. `config/themeConfig/sidebar/` 对应文件该条目 link；
3. `config/vite/rewrites.ts`、nav 等涉及旧名的映射；
4. 全仓其他 md 指向旧名的引用链接；
   完成后全仓搜旧名（带 `.md` 与不带两种形式）确认零残留。

## 术语标注规范

**不可变区域**（一个字符都不得修改：不打标签、不改大小写、不改写）：

- 围栏代码块（` ``` ` 起止之间的全部内容）；
- 行内代码（`` ` `` 反引号包裹的文本）；
- 链接文本与链接地址。

标题已移出不可变区域（标题按「标题优化规范」处理，但不打标签）。

打标签为强制动作：目标范围内所有文档均须按本规范打标签并入表；不得以目录/风格为由跳过。
禁止全局批量替换：每一处按上下文判断，仅自然语言正文才打标签。
术语范围：产品、框架、协议、算法、文件格式、行业专有名词。
全称规则：TS→TypeScript、JS→JavaScript；行业固有缩写（SVG、CSS、API、JSON、URL、PNG、WebP、GIF）保留。
排除清单（不打标签不入表）：v-\* 指令、ref/reactive/computed 等 API 标识符、requestAnimationFrame 等函数名、通用编程词汇。
首字母大写：lottie→Lottie、canvas→Canvas、base64→Base64；官方固定写法保持。
标签语法：先搜仓库 `<word` 既有用法借用其风格；无则用 `<word text="术语" />`。
同一段落同一术语只打一次；已打过标签的保持原样，写法不合规则修正并同步词汇表。

## 去AI化与表达规范

删除套话：「让我们」「你可以」「众所周知」「总之」「值得一提的是」、emoji、感叹号堆叠。
结论先行：段首一句结论再给理由；多用陈述句祈使句，句子缩短。
同一概念全文只用词汇表唯一术语（全称），禁止同义替换与缩写混用。
只改表达不改事实：代码、命令、链接、数值保持原样。

## 结构补充规范

代码：统一带语言标签围栏代码块；补语言标签只改围栏起始行，不改内部。
表格：三项以上对比必须用表格。
流程图：Mermaid（flowchart / sequenceDiagram）；未集成则编号步骤。
标题层级最深 `###`，不跳级。

## 进度落盘与中断恢复

每批结束更新 PROGRESS，模板：

```
# content-fix 进度
## 最后更新
<时间>（第 N 批完成）
## 已处理
- [x] src/xxx.md（含改动说明）
## 未处理
- [ ] src/yyy.md
## 待办事项
- [ ] <未完成项>
## 统计
词汇表共 N 条（本批新增 M）；元数据共 N 条（本批新增 M）
```

新会话先执行接管检查，不重复已处理、不遗漏未处理。
每批给出建议 commit 命令文本由用户手动执行。

## 终端零命令约束

禁止执行任何终端命令（PowerShell/cmd/bash/git/npm 等）：

- 改名：编辑器重命名；搜索：编辑器全仓搜索；读写：文件编辑工具；
- 提交：只给建议命令文本；确需命令的操作停下请示用户。

## 禁止事项

- 不得执行任何终端命令。
- 不得保留 `---` frontmatter 块。
- 不得将缩写（TS/JS）登记入词汇表（固有缩写除外）。
- 不得修改代码块/行内代码内任何字符。
- 不得用全局查找替换批量打标签或改大小写。
- 不得移动文档目录（须用户确认）。
- 不得跳过任何目录的术语打标签。
- 不得用非递归枚举断定无 md。
- 不臆造 JSON 字段、不删除既有条目。
- 不得将排除清单标识符写入词汇表。
- 不得在标题中插入 `<word` 标签。
- 不确定的技术事实保留原文，不得编造。
- 正常结束前不得跳过 PROGRESS 回写。
