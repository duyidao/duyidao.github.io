# 文档内容规范化

用于处理 `src/` 下 Markdown 知识文档的标题与正文质量。只改内容表达，不擅自改动代码块内的示例代码、组件标签和文件路径。

## 规则一：全篇有且仅有一个大标题

- 每个文档必须有且仅有一个 `#` 一级标题，作为全文唯一的大标题
- 一个文档原本用两个 `#` 分两大块（如 `# 变量` + `# 严格模式`），按下列优先级处理：
  1. 文档本身是两篇独立知识点的拼接，且文件名能覆盖两者 → 合并为一个大标题，原两个标题降级为 `##`
  2. 文档是同一主题的不同阶段 → 保留第一个 `#` 作为大标题，另一个降为 `##`
- 完全没有 `#` 的文档（如 `read/css/...` 系列以 `##` 开头），把原最高层级标题提升为 `#`，其余层级整体上移一级，保证不出现层级跳跃
- 首页 `src/index.md` 使用 `layout: home` 的 frontmatter，不适用本规则，跳过

## 规则二：标题禁止任何形式的序号

标题是导航标签，不是目录编号。任何层级的标题（`#` 到 `####`）都不得携带序号，编号信息交给侧边栏与自动目录生成。

**必须清除的序号形态**（全部实测存在于 `src/`，共 26 个文件 82 处）：

| 形态            | 实例                                                                | 出现位置                          |
| --------------- | ------------------------------------------------------------------- | --------------------------------- |
| 汉字顿号序号    | `### 一、初始化项目`、`### 二、编写源码与配置`                      | `read/vite/深入浅出Vite/`         |
| 阿拉伯数字点号  | `### 1. 瓦片树与地理参考判定`、`### 2. b3dm`                        | `work/南网/无人机/`               |
| 章节序号        | `# 第一章 ECMAScript6简介`、`# 第十二章 Proxy`                      | `read/javascript/ES6标准入门/`    |
| 圈号            | `## ① 创建实例`、`## ② 配置参数`                                    | 全库检索式                        |
| 括号序号        | `## （一）基础用法`、`## (1) 安装`                                  | 全库检索式                        |
| 汉字量词 + 序号 | `## 方案一`、`### 步骤一`、`### 技巧三`、`### 场景一`、`### 问题四` | `practice/`、`read/css/`、`work/` |

**清除方法**：不是把序号删掉了事，而是删序号的同时让标题自解释。判定标准同规则三——去掉序号后标题仍要准确说明该段讲了什么。

| 原写法                               | 不合格改法（只删序号）       | 合格改法                             |
| ------------------------------------ | ---------------------------- | ------------------------------------ |
| `### 一、初始化项目`                 | `### 初始化项目`             | `### 用 npm init 初始化 Rollup 项目` |
| `### 二、编写源码与配置`             | `### 编写源码与配置`         | `### 入口源码与 rollup.config.js`    |
| `### 技巧一：渐变颜色可以设置透明色` | `### 渐变颜色可以设置透明色` | `### 渐变透明度实现遮罩效果`         |
| `### 步骤一：Whistle 代理规则配置`   | `### Whistle 代理规则配置`   | `### Whistle 侧配置代理规则`         |
| `# 第一章 ECMAScript6简介`           | `# ECMAScript6简介`          | `# ECMAScript 6 的由来与规范演进`    |

**例外**：标题中出现数字属于专有名词或技术事实时保留，不视为序号——`Vue3`、`ES6`、`b3dm`、`3D Tiles`、`WGS84`、`100vh`、`8 种核心技巧`（标题内描述性数量，不是排序编号）。

**批量核对命令**（PowerShell，跳过代码围栏）：

````powershell
$files = Get-ChildItem src -Recurse -Filter *.md
foreach ($f in $files) {
  $inFence = $false; $ln = 0
  foreach ($l in [System.IO.File]::ReadAllLines($f.FullName)) {
    $ln++
    if ($l -match '^\s*```') { $inFence = -not $inFence; continue }
    if ($inFence) { continue }
    if ($l -match '^(#{1,6})[ \t]+(.+)$' -and $matches[2] -match '^第[一二三四五六七八九十0-9]+[章节篇]|^[一二三四五六七八九十]+[、．.]|^[0-9]+[、．.]\s|^[（(][一二三四五六七八九十0-9]+[）)]|^[①②③④⑤⑥⑦⑧⑨⑩]|^(问题|方式|步骤|阶段|方案|情况|场景|方法|技巧|模式|要点|案例|Part|Step|Chapter)[一二三四五六七八九十0-9]+') {
      "{0}|{1}|{2}" -f $f.FullName, $ln, $l
    }
  }
}
````

改完后重跑该命令，输出必须为空。

## 规则三：标题必须贴合其下内容

- 逐个标题读其覆盖的正文，判断标题是否准确概括该段落
- 标题空泛、与内容不符、或只是编号占位（如 `## 一`、`## 二`）时，依据正文实际内容重写
- 允许保留 `## 动手实操`、`## 完整代码` 这类功能性标题，但前提是正文确实是操作步骤或完整代码；若正文是原理讲解，必须改名
- 层级关系要正确：子标题必须属于父标题的语义范围，不能出现 `## Babel` 之下再挂 `### 含义` 这种跨主题错位

## 规则四：标题不得重复，但禁止敷衍式改名

这是本 skill 最容易做错的一条。

**禁止的做法**（用户明确不接受）：

- 原文 `## 总结` → 改成 `## Vue3 总结`、`## 本章总结`、`## 总结一`
- 只加前缀/后缀、只加序号、只换同义词（`总结`→`小结`、`概述`→`简介`）
- 保留原词再拼接范围词

**要求的做法**：从该标题下正文的**实际结论**中提炼，做到「只看标题就知道这一段讲了什么独特的事」。

判定标准：把同一文档内所有标题排成一列，任意两个标题互换位置都会让读者产生困惑，才算合格。

示例对照：

| 原标题    | 正文内容                                       | 不合格改法      | 合格改法                                    |
| --------- | ---------------------------------------------- | --------------- | ------------------------------------------- |
| `## 总结` | 讲了 Proxy 与 Reflect 的配合、以及拦截器陷阱   | `## Proxy 总结` | `## Proxy 与 Reflect 的拦截协作机制`        |
| `## 总结` | 讲了三种方案对比与选型结论                     | `## 本章总结`   | `## 三种方案的性能对比与选型建议`           |
| `## 概述` | 讲了该 API 的历史来源与浏览器支持              | `## 概述一`     | `## API 的历史演进与浏览器兼容性`           |
| `## 实现` | 讲了用 IntersectionObserver 做懒加载的具体写法 | `## 代码实现`   | `## 基于 IntersectionObserver 的懒加载实现` |

同一文档内若确有多个收尾性段落，分别按各自结论命名，不允许出现两个语义等价的标题。

## 规则五：正文去口语化

改写为知识文档的客观陈述语气，替换下列口语痕迹：

- 第一人称叙述：`我们来看一下`、`我给大家演示`、`咱们`、`笔者` → 删除主语或改为 `下面以…为例`
- 口语连接词：`那么`、`所以说`、`其实吧`、`这里要注意一下哦` → `因此`、`需要注意的是`
- 语气助词与感叹：`吧`、`呢`、`啊`、`啦`、`~`、`！` 在陈述句中删除
- 主观评价：`超级好用`、`非常简单`、`坑爹`、`踩坑了` → `易用性较高`、`实现较为简单`、`常见问题`
- 网络用语与缩写口语：`搞一下`、`整一个`、`拿来即用` → `实现`、`构建`、`开箱即用`
- 冗余铺垫：`众所周知`、`不言而喻`、`话不多说` 直接删除
- 保留 `刀刀博客` 等专有名词、代码注释原文、引用块内原作者口吻不改

## 规则六：检查知识性错误

逐段核对技术陈述，重点排查：

- API 名称、参数、返回值拼写与语义（如 `addEventListener` 第三参数、`Promise.all` 与 `allSettled` 的区别）
- 版本号与特性归属（如 ES6 与 ES2015 的关系、Vue2 与 Vue3 的 API 差异）
- 概念混淆（`let` 与 `const` 的暂时性死区、`==` 与 `===` 的转换规则、宏任务与微任务顺序）
- 因果表述倒置（把「因为 A 所以 B」写成「因为 B 所以 A」）
- 数字与结论不符（文中说「三种」实际列了四种）
- 中英文术语指代不一致（前文叫「事件循环」，后文叫「事件轮询」指同一概念需统一）

发现错误时直接修正，并在回复中逐条列出「原文 → 修正 → 依据」，不静默改动技术结论。

## 执行流程

1. 定位目标文档，先通读全文，列出所有标题及其覆盖内容
2. 统计一级标题数量，按规则一调整层级
3. 按规则二清除所有标题中的序号，同时保证标题自解释
4. 按规则三逐条核对标题与内容的对应关系
5. 按规则四重写不合格标题，自查是否存在敷衍改名
6. 按规则五逐段去口语化
7. 按规则六核对技术表述，列出修正清单
8. 重跑规则二中的批量核对命令，确认序号标题归零
9. 输出改动摘要：标题变更表 + 正文改写要点 + 知识性错误清单

## 禁止事项

- 不改动代码块内容（缩进、引号、注释除外，仅修正明显笔误）
- 不改动 `<word text="..."/>` 等组件标签（组件问题交给 doc-component-checker）
- 不改动 frontmatter 中的 `layout`、`hero` 等站点配置
- 不新增原文没有的知识点，不删减原文的技术要点
- 不为了凑标题而虚构正文中不存在的结论
