# 文档内容规范化

只改内容表达。不擅自改代码块、组件标签、文件路径、站点配置。

## 范围

- **默认**：只处理用户点名的 `.md`。未点名先问。
- **跳过**：`src/index.md`（`layout: home`）。
- 绝大多数文档没有 frontmatter，标题写在正文里。

## 与其他文档 skill

同一批点名文件，顺序：

1. [doc-format-fixer](../doc-format-fixer/SKILL.md) 先做完（`--fix` 会改行号）
2. 本 skill
3. [doc-component-checker](../doc-component-checker/SKILL.md) 最后做（`文档元数据.json` 的 `title` 要跟定稿一级标题走）

MD041/MD025 的层级机械调整由 format-fixer 完成。本 skill 只在其结果上做**语义重写**，不反复调层级。

## 站点约定：不要动「会变成图」的围栏

`::: code-group` 里的 ` ```mermaid [标题] `（以及单独的 ` ```mermaid `）会渲染成流程图 / 时序图，这是正常业务。

- 不把 mermaid 源码改成截图、说明文字或普通 `js` 代码块
- 不改 tab 标题（`[泳道图]`、`[时序图]`、`[流程图]` 等），它们还要匹配 `customIcon` / `public/svg/`
- 围栏内示例代码：只修正明显笔误（错别字），不改逻辑、缩进风格和注释口吻

## 规则一：全篇有且仅有一个 `#`

- 两篇知识点拼在一个文件、且文件名能覆盖两者：合成一个 `#`，原两个降为 `##`
- 同一主题不同阶段：保留第一个 `#`，其余降为 `##`
- 完全没有 `#`：把原最高层提到 `#`，其余上移一级，避免层级跳跃

## 规则二：标题禁止序号

任何 `#{1,6}` 标题都不得带排序编号。编号交给侧边栏和目录。

必须清掉：`一、` / `1.` / `第一章` / `①` / `（一）` / `方案一` / `步骤一` / `技巧三` 这类。

**不是只删序号**，删完标题仍要自解释：

| 原写法 | 不合格 | 合格 |
| --- | --- | --- |
| `### 一、初始化项目` | `### 初始化项目` | `### 用 npm init 初始化 Rollup 项目` |
| `### 步骤一：Whistle 代理规则配置` | `### Whistle 代理规则配置` | `### Whistle 侧配置代理规则` |

**保留**（不是排序编号）：`Vue3`、`ES6`、`b3dm`、`3D Tiles`、`100vh`、`8 种核心技巧`。

## 规则三：标题贴合其下正文

读标题覆盖的正文再改。空泛、错位、编号占位（`## 一`）必须按正文重写。子标题必须落在父标题语义范围内。

## 规则四：标题不得重复，禁止敷衍改名

用户不接受：加前缀/后缀、加序号、换同义词（`总结`→`小结`、`概述`→`简介`、`总结`→`本章总结`）。

要从该段**实际结论**提炼，做到只看标题就知道这段讲了什么独特的事。同一文档内任意两个标题互换都会让人困惑，才算合格。

`概述` / `动手实操` / `完整代码` / `注意事项`：

- 文中仅出现一次、且正文确实是总述 / 步骤 / 整段代码 / 注意点 → 可以保留
- 同文档出现多次，或正文其实是原理/对比/选型 → 必须按正文重写，不能靠加「本章」敷衍

## 规则五：去口语化

知识文档客观陈述。替换第一人称铺垫、`那么`/`其实吧`、语气词、`超级好用`/`坑爹`、`搞一下`。保留专有名词、代码注释原文、引用块里原作者口吻。

## 规则六：知识性错误

核对 API、版本归属、易混概念、因果、数量与列举是否一致、中英术语前后是否同一指称。修正时在回复里列出「原文 → 修正 → 依据」，不静默改技术结论。不新增原文没有的知识点，不删原文技术要点。

## 执行流程

1. 通读点名文档，列出标题及其覆盖内容
2. 规则一到六依次处理
3. 自查：未改 mermaid / code-group 标题 / `<word>` / 代码逻辑
4. 输出：标题变更表、正文改写要点、知识性错误清单

## 禁止

- 改 `<word text="..."/>`（交给 component-checker）
- 改 frontmatter 的 `layout` / `hero`
- 为凑标题虚构正文没有的结论
- 未点名就批量改 `src/` 下所有文档
